# Windows 发布与验收

本轮目标为 Windows x64，Windows 10 1809 及以上与 Windows 11。代码阶段不代替原生编译、真机听感或安装验收；开发入口见 [安卓开发指南](../安卓开发指南.md)，批次状态见 [Windows 开发计划](../windows开发计划.md)。

## GitHub Actions 打包

[Windows 工作流](../.github/workflows/release-windows.yaml) 使用 `windows-2022`、Flutter 3.47.7 和 runner 自带的 Visual Studio C++ 工具链、Inno Setup 6，支持两种触发方式：

- 在 GitHub Actions 选择“构建 Windows 应用”并执行 **Run workflow**，选择待打包分支；成功后从本次运行的 Artifacts 下载 `bobomusic-<版本>-windows-x64`，保留 14 天。手动运行只生成产物。
- 推送 `v<版本名>` 标签时自动打包，并把 ZIP、安装 EXE 和各自的 `.sha256` 上传到该标签对应的 Release。标签必须与 `pubspec.yaml` 的版本名一致，例如 `version: 3.0.0+300` 对应 `v3.0.0`。

手动运行入口要求工作流文件已合入 GitHub 仓库默认分支，之后可在 **Run workflow** 中选择待打包分支，见 [GitHub 手动运行说明](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow)。

流程依次执行锁文件校验、`dart analyze`、`flutter test`、Windows x64 Release 构建、C++ 运行库补齐、便携包与安装包生成；任一步失败都不会发布 Windows 包。便携包复用 `package.ps1`，安装包复用 `installer.iss`；生成的包包含应用目录及所需的 x64 C++ 运行库。

Windows 发布使用仓库内置 `GITHUB_TOKEN`，只给发布任务授予 `contents: write`，无需 Android 的签名 Secrets 或 `RELEASE_TOKEN`。Android 和 Windows 的 Release 写入共用并发锁，附件追加到同一个 Release。当前流程没有配置 Windows 证书签名，产物为未签名包；首次 CI 原生编译及下载后的运行、安装与升级仍需所有者验收。

## 所有者本地构建与打包

使用 Flutter Windows 所需的 Visual Studio C++ 桌面工具链及 Windows SDK。媒体中心桥使用 SDK 自带 C++/WinRT 头和 `windowsapp.lib`、`runtimeobject.lib`，没有独立音频进程或第二个播放器。

以下命令由所有者从仓库根目录执行；新增原生代码需要完整重启，热重载不会更新桥接器。

```powershell
flutter pub get
dart analyze
flutter test
flutter build windows --release
powershell -ExecutionPolicy Bypass -File windows/package.ps1
```

`package.ps1` 只归档已有 Release 目录并生成 SHA256，不执行构建、不覆盖已有同名产物。分发完整 ZIP；解压到可写目录后运行 `bobomusic.exe`，不能只复制 exe。构建产物与打包输出在被 Git 忽略的 `build/` 下。

安装包使用 Inno Setup 6。从 `pubspec.yaml` 读取版本名，传给安装脚本；示例中的 `ISCC.exe` 需已加入 PATH：

```powershell
$releaseVersion = ((Get-Content pubspec.yaml | Select-String '^version:').Line -replace '^version:\s*', '').Split('+')[0].Trim()
ISCC.exe "/DAppVersion=$releaseVersion" windows/installer.iss
```

安装器按当前用户安装到本地 Programs 目录，不申请管理员权限；AppId 保持固定。自定义构建目录时传 `/DBundleDir=绝对目录`，输出目录传 `/DOutputDir=绝对目录`。正式分发前由所有者完成自有可执行文件和安装包签名，并在干净机器检查运行库依赖与 SmartScreen 表现；本仓库不保存证书与密钥。

## 数据与升级边界

- 数据库固定到应用支持目录下的 `databases/bobomusic3.db`；偏好仍使用现有插件位置。Windows 资源中的 CompanyName、ProductName 保留，以免插件计算出另一个用户数据目录。
- 首次迁移会从旧 FFI 默认目录、启动目录及程序目录中检测旧库。只有唯一候选且快照校验通过才迁移；保留原库，有目标库时不覆盖。发现多份候选或损坏库会进入启动错误页。
- 更换程序目录后首次启动，如果旧库没有随当前路径被发现，应先关闭应用、备份数据，再将旧数据库及可能存在的 WAL/SHM 保留在旧程序目录，从旧目录启动新版执行迁移；不要只复制活动数据库的主文件。
- 下载放在系统下载目录下的 `啵啵音乐/`；缓存位于应用缓存目录；导入副本位于文档目录的 `啵啵音乐导入/`。移除扫描目录配置只改变后续扫描范围。
- 安装、升级和卸载脚本不删除用户数据库、偏好、导入副本或下载。便携包指程序免安装，用户数据仍保存在系统用户目录。

## 所有者验收清单

- [ ] 干净 Windows 10/11 启动；从中文和带空格的程序目录启动；修改工作目录后再次启动。
- [ ] 旧库迁移后核对歌单、喜欢、歌词、历史、队列；存在损坏库和多份旧库时能看到明确错误。
- [ ] 在常用分辨率、125%/150% 缩放、最小窗口、最大化和断开外屏后检查布局与恢复位置；回归明暗和十色主题。
- [ ] 五源实际播放、暂停续播、切歌、倍速、静音和恢复；搜索、队列、歌词 seek、全屏内容页切换时不断播。
- [ ] 系统媒体面板的标题、歌手、封面、进度和播放状态正确；快速切歌不出现旧封面覆盖。
- [ ] 媒体键及系统面板的播放、暂停、上一首、下一首和可用 seek/倍速入口作用于同一播放器；最小化、锁屏和睡眠唤醒后仍可控制。
- [ ] 关闭窗口退出并保存进度、音量、倍速与窗口状态；重开后恢复；最小化继续播放。
- [ ] 多目录扫描、元数据损坏、拒访与移动盘拔出不会误删收藏和其它目录歌曲；导入同名文件不覆盖。
- [ ] 下载中暂停、继续、取消与重试；服务器不支持续传时完整重下；断网后已下载歌曲可播放；打开所在文件夹可用。
- [ ] 干净机器解压完整 ZIP 可运行；首次安装、覆盖升级、卸载再安装后用户数据保留；核对签名、运行库和校验和。

SMTC 的系统界面入口随 Windows 版本变化；无法在某个面板看到 seek 或倍速入口时，先区分系统是否展示该入口与桥接命令是否工作，不在应用里虚构系统支持状态。
