# MEM-3 · 酷我歌手名残留 `\u0026` / 反斜杠

## 现象

部分歌曲歌手名显示为 `A2O LITE\u0026A2O`；第一版修复后变成 `A2O LITE\&A2O`（多个 `\`）。

## 根因链

1. 酷我数据两条链路：老接口 JSON 走 `jsonDecode`（自带 `\uXXXX` 解码，不漏）；**榜单 SSR 页可见文本**（`<p class="artist">`）不经过 JSON 解码，Nuxt 未解干净的 `\u0026` 原样漏出。
2. `decodeKuwoText` 原本只处理 HTML 实体（`&amp;` 等），不处理 JS 转义。
3. 第一版修复用 `\\u([0-9a-f]{4})` 只吃**一道**反斜杠——真机数据存在**双重转义** `\\u0026`，解一层后残留 `\`。

## 修复（ffb6614）

- `decodeKuwoText` 接入 `_decodeJsEscapes`：正则 `\\+uXXXX` 允许**连续多道反斜杠**，`\/` 一并处理；
- `_unescapeJsString`（封面 URL 转义）合并到同一解码器，URL 同形态受益；
- 该函数是酷我**所有文本出口**的必经点——新增出口必须过它，别自建清洗。
- 测试：`test/kuwo/kuwo_parse_test.dart` 单重转义 + 双重转义不残留反斜杠 + 旧接口字段路径。

## 遗留

**已入库的脏数据不会自愈**：tracks 表里旧的歌手名要等同一首歌重新 upsert（重播/收藏）才被清洗后数据覆盖。存量全表清洗未做（需所有者拍板）。
