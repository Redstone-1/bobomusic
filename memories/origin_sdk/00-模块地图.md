# origin_sdk · 模块地图（v3）

> 核对：2026-10-29，`11e3126` 后的音源修复。依据桩测试、接口样本与所有者真机反馈：本轮接口整体较稳定，QQ 仍会受到服务端限制；其余能力未逐项记录。“可用/回退”描述代码路径，不能据此承诺接口持续在线。

## 一句话模型

五个在线音源实现 `OriginService`，搜索、榜单、播放和下载分别按当前选择或曲目 origin 分发；歌词使用独立 `LyricService`。SDK 与 UI 的 OriginType 是不同枚举，经 mapper 按 value 桥接。

## 入口与核心文件

| 文件 | 职责 |
| --- | --- |
| `lib/origin_sdk/origin_types.dart` | OriginService、SearchItem、MusicItem、MusicUrl、ChartHit、OriginChart 等契约 |
| `lib/data/origin_service.dart` | 可替换五源实例 biliApi / kuwoApi / neteaseApi / qqApi / qianqianApi |
| `lib/data/mappers.dart` | SDK → Track 映射；SearchItem 优先取内嵌 musicList 首条 |
| `lib/origin_sdk/bili/` | BiliApi、BiliAuth、错误类型、WBI 签名、票据和解析 |
| `lib/origin_sdk/kuwo/kuwo_api.dart` | 新旧搜索、anti.s 取流、官方 bang 榜、热榜 SSR 回退与文本清洗 |
| `lib/origin_sdk/netease/netease_api.dart` | 免加密搜索/playlist 榜单、免费曲目过滤、outer/url 取流 |
| `lib/origin_sdk/qq/qq_api.dart` | QQ 搜索、免费过滤、vkey 取流；当前无榜单卡 |
| `lib/origin_sdk/qianqian/qianqian_api.dart` | MD5 参数签名、搜索、bd/list 新歌榜、tracklink 取流 |
| `lib/origin_sdk/lyric/` | 三顺位歌词搜索、候选取词、LRC 解析与翻译合并 |

```text

```

## 关键状态与回退链

- BiliAuth.ensure / refresh 通过 _inFlight 合并并发；内存和持久化材料精确按 24 小时有效期检查，并保留版本门控。refresh 跳过旧缓存，主页 cookie 不可得时尝试 spi。BiliApi 非 playurl 请求注入 cookie，playurl 明确不带 cookie。
- BiliApi 独立识别 code=0 + data.v_voucher；风控、签名失效和 HTTP 412 最多重刷鉴权并重新签名一次，普通业务错误与 429 不重试。解析结构变化转为 BiliParseError，见 [MEM-4](../bugs/MEM-4-B站与播放链路回归.md)。
- B 站取流先查 TTL/LRU；缺 cid 时 searchDetail 补齐，多 P 取首条；仍缺失才抛 BiliInvalidIdError。dash 按带宽取音频，保留 backupUrl 和 Referer，contentType 为 video/mp4。
- QQ 取流按 M800 MP3 → M500 MP3 → C400 AAC 选择可用音质，保留 CDN 备链和对应 MIME；服务拒绝/网络/格式错误不当作音质不足循环请求。三档无地址只提示可能的权限或版权限制，不直接断言 VIP。
- QQ 搜索免费过滤后为空时每次最多补查三页；SearchResponse.current 为最后消费原始页，hasMore 显式表示是否仍有原始页。达到补页预算不等于到底；会话内有界缓存 file.media_mid 用于音频文件名，见 [MEM-5](../bugs/MEM-5-QQ音质与分页.md)。
- 酷我搜索新接口失败/空结果后试老接口。榜单主链已改为 kbangserver.kuwo.cn/ksong.s 官方 bang 接口；仅热歌榜 16 失败后回退 hotHits 的 SSR 解析。飙升榜失败直接抛类型化错误，由单卡展示失败。
- 旧 hotSongs 能力仍留在 SDK，但当前广场不使用它构造主题榜。不能继续沿用“官方多榜不可得”或把搜索主题卡当作现行榜单。
- 歌词 search 按网易 → LRCLIB → timelessq 返回首个非空候选集；fetch 只获取该候选所属源，失败返回 null，不会自动继续尝试其它源。LRC 两位小数按百分秒 ×10 解析，翻译通过 mergeLrcTranslation 合并。

## 易踩坑

- playurl 不带 cookie、音频请求带 Referer 是既有风控约束；签名与 headers 不能随意省略。
- SDK 的 `origin.name` 是中文显示名，映射到数据层要使用 `origin.value`；五源与下载/播放路由需一起核对。
- SDK 缺 cid 自愈只保证可尝试取第一 P，不能替代搜索页识别多 P/合集并进入列表的业务语义，见 [MEM-1](../bugs/MEM-1-合集误播.md)。
- 酷我文本统一走 decodeKuwoText，兼容 HTML 实体及连续多道反斜杠转义；官方 JSON 榜单出口也要经过清洗，见 [MEM-3](../bugs/MEM-3-kuwo转义泄漏.md)。
- 网易、QQ、千千过滤后的结果只覆盖当前免费口径，结果数量可能比接口 total 少。QQ 的显式 hasMore 优先于过滤后条目数量；分页仍按 id 去重，不能把过滤空页误判为原始页耗尽。
- 解析测试只能验证样本，旧接口实测日期不是长期可用性保证。

## 排查入口

| 症状 | 先查 |
| --- | --- |
| B 站搜索后取流缺 cid | getMusicUrl 的 searchDetail 补齐、详情解析和 BiliId |
| 取流 403 / 解码失败 | Referer、cookie 特判、MusicUrl → PlaySource 的 headers/contentType |
| 某一榜单失败 | plazaChartDefs 的 key、所属源 getChartHits 与其回退链 |
| 歌手名残留转义 | 新出口是否绕过 decodeKuwoText |
| 切源后播放/下载来自错误平台 | Track.origin、mapper、两条取流分发链 |
| 歌词候选有但获取失败 | 候选 source 与 fetch 对应实现，不能误认为 fetch 会跨源回退 |

解析测试入口为 `test/bili/`、`test/kuwo/`、`test/netease/`、`test/qq/`、`test/qianqian/` 和 `test/lyric/`。
