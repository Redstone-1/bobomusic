# 本地扫描事件流与扫描舱

> 核对：2026-11-03，源码基线 `073cd0a`。多目录、失败保留和同名导入按实现及替身测试核对；移动盘拔出、系统权限和大库体验仍需所有者实测。

## 覆盖范围

`lib/data/local_audio_scanner.dart`、`lib/features/playlist/local_scan_controller.dart`、`local_scan_panel.dart`、`scan_failures_dialog.dart`、`local_library_directories.dart`、`lib/data/local_audio_importer.dart`，以及 `playlist_detail_page.dart` 的扫描接入。旧版扫描是 `Isolate.run` 一次性返回，UI 只能显示骨架屏；现在扫描过程有文件/进度事件，列表区域显示内嵌扫描舱。

## 数据层

- `LocalAudioScanner.scanTask()` 是生产入口：`Isolate.spawn` + `ReceivePort`，遍历和元数据读取在后台 isolate；每 8 个文件批量发送 `LocalScanFiles`，失败即时 `LocalScanFileFailure`，累计进度 `LocalScanProgress`，结束 `LocalScanDone`。
- 事件是 `sealed class LocalScanEvent`；注入 `AudioMetadataSource` 的测试路径在主 isolate 用 `scheduleMicrotask` 发送同一套事件，不启动 isolate。
- `scan()` 保留为一次性 API，内部消费事件流返回 `LocalScanResult`；`scanFiles()` 仍走导入路径，不参与扫描舱。
- `LocalScanResult` 同时返回 `roots` 和 `inaccessibleDirectories`，用于限定本次可清理范围；`failed` 保留路径列表，`failures: List<ScanFailure>` 保存 path + reason。旧 override 只填 `failed` 时，controller 会补 `读取失败` 原因。
- `LocalScanTask.cancel()` 关闭 `ReceivePort` 并 `Isolate.kill(immediate)`；取消后不写库。元数据读取 `getImage: false`，扫描不提取封面图。

## 目录与导入边界

- Windows 本地音乐页经 `localLibraryDirectoriesProvider` 维护 `windows_music_directories` 偏好，用系统目录选择器增加规范化绝对目录；移除配置只缩小后续扫描范围，不删除曲目、原文件或下载。
- `scanLocalLibraryTask(roots: ...)` 将选定目录送入后台扫描；不存在/拒访目录记入不可访问结果。Controller 传 scannedRoots=result.roots、retainedPaths=result.failed，只要存在不可访问目录就禁用本次删除；没有该问题时也只清理扫描根下的未再现项。
- `TrackRepository.syncLocalTracks` 保留失败文件和其它目录曲目，先算差集，再按 900 个 IN 参数分批删除；取消不会把不完整结果写成全量结果。
- `importAudioFilePaths` 异步复制到文档目录 `啵啵音乐导入/`；同名不同内容加 `(n)` 后缀，相同大小和 MD5 复用副本。所选文件扫描后增量 upsert，不拿它清理整个本地库。

## 状态层

- `LocalScanController`（`ChangeNotifier`）持有 `phase`（idle / scanning / syncing / done / failed）、`scanned/indexed/failed`、`recentPaths`（最多 12 条）、`failures`、`error`。
- 事件按 70ms 节流通知；`start()` 等到 `LocalScanDone` 后的 `syncLocalTracks` 完成才返回；流提前关闭且没有 done 视为失败。
- `cancel()` 只在 scanning 有效；进入 syncing 后不可取消，避免事务半写。
- 写库成功后用 `result.tracks.length` 和 `failures` 校准计数；写库失败进入 failed。

## UI

- `playlist_detail_page` 在 `_scanController != null` 时把列表区域换成 `LocalScanPanel`（内嵌，保留头部/搜索框/底部 Dock）；普通列表加载仍用 `SkeletonListView`。
- 面板包含扫描线/网格 painter、完整路径文件流（`ListView` 自动滚到底、最多 12 条）、大号计数、阶段条、取消按钮；系统关闭动画时停扫描线。
- 完成态在页面停留 600ms 再关闭；有失败时用 `showScanFailuresDialog`（`AppDialog` 居中、限高 320、完整路径与读取失败原因）。
- 扫描中离开页面：页面 `dispose` 取消扫描；`_scan()` 的 `finally` 负责 dispose controller。

## 回归入口

- `test/data/local_audio_scanner_test.dart`：`scanTask` 事件顺序、失败原因、取消和不可访问目录。
- `test/data/local_audio_importer_test.dart`：同名不同内容保护与相同文件复用；多目录保留规则同时查看 `test/data/` 的 Repository 测试。
- `test/features/playlist/local_scan_controller_test.dart`：计数、失败列表、取消、写库失败、旧 `failed` 回退。
- `test/features/playlist/local_scan_panel_test.dart`：完整路径文件流与取消按钮。
- `test/widget_test.dart`：扫描闭环、失败文件弹窗。
- 真机/桌面需验证多目录、拒访、移动盘拔出、同名导入、大库滚动、取消时序和完成态，以及扫描舱与底栏的层级。

## 易踩点

- 扫描事件按 8 个文件批量发送；UI 侧只保留最近 12 条，不能每个文件都触发整页 setState。
- `LocalScanResult.failed` 保持兼容；新 UI 读 `failures`。
- 取消只在 scanning 阶段；syncing 阶段必须等事务完成。
- 扫描极快时页面固定停留 600ms；widget 测试 pump 需多留一帧。
- `localScanTestOverride` 必须经 `scanLocalLibraryTask` 才能驱动扫描舱与失败弹窗。
