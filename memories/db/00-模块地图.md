# db · 模块地图

> 表结构 SQL 与 API 速查见 `项目文档.md` 第 6 章；本文补**表即歌单模型的约束链**与**匹配粒度陷阱**。基线 0aac7bb，2026-10-24 核对。

## 一句话模型

一个歌单 = 一张 SQLite 表（表名=歌单名，中文可用），歌单顺序不存排序列，而是存 `prev`/`next`（相邻行的 playId）双向环形链表 + `isFirst`/isLast` 标记；读取时由 `getUpdatedMusicList` 全表重建链表并回写漂移部分。

## 链表重建算法（getUpdatedMusicList）

1. `queryAll(tabName, groupBy: 待播放列表 ? "playId" : "name", needOrder: 内置表/我喜欢 ? true : false)`
   - 去重：`WHERE id IN (SELECT MIN(id) ... GROUP BY <groupBy>)`——同名歌曲在普通歌单只保留最早一行；待播放列表按 playId 去重（允许同名重复添加）。
   - 排序：`本地`/`我喜欢` 按名称升序；自定义歌单与待播放列表保持自增 id 顺序（即插入顺序）。
2. 逐行计算 `prev = 上行 playId`、`next = 下行 playId`（首尾相接成环），与库值不一致就 `db.update` 回写。
3. ⚠️ 回写用 `update(table, row)`，其 where 是 `mid =? OR playId =?`——见下「匹配粒度陷阱」。

## 匹配粒度陷阱（⚠️ 已实证，改任何 delete/update 前必读）

| API | where 条件 | 会误伤什么 |
| --- | --- | --- |
| `update(table, row)` | `mid =? OR playId =?` | 同一首歌（同 mid）被加入两个歌单不受影响（分表），但**同表内同 mid 两行**（先按 name 去重前的脏数据）会一起被改 |
| `delete(table, param)` | `mid =? OR name=?` | **按名字删会删掉同名所有行**；播放内核删待播放列表传的是 playId，但条件里没有 playId —— 若某行 name 恰好等于该 playId 才靠 OR 命中，实际删除依赖 mid/playId 不相同时的失配……**即 `removePlayerList` 的删除条件实际靠 `mid = playId` 传入命中 mid 列**（调用点传 `m.playId`，mid≠playId 时删不掉！靠 `name=?` 也对不上 → 需实测确认行为，标记：未展开） |
| `queryByParam(table, param)` | `mid =? OR name LIKE %?% OR playId =?`，`GROUP BY playId` | playId 为空串的行会被合并成一条 |
| `DBCollection.queryByParam` | 覆写仍 `GROUP BY playId`（该表无此列） | 无调用点，暂未触发（12.6） |

其它已知：表名字符串插值进 SQL（12.2）；`我喜欢`/`待播放列表` 建表语句 `author INTEGER` 笔误（12.7）；sqflite 动态类型下仍能存 TEXT。

## 数据不变量（迁移/重构时必须保持）

1. 同一 `MusicItem` 进不同歌单会有**不同 playId**（每次收藏/加入重新 uuid）——「我喜欢」状态判定、当前播放高亮都依赖 playId 或 mid 双重判定。
2. `prev/next` 存的是**同表内相邻行的 playId**，环形（首.prev=尾，尾.next=首）。
3. 合集表名 `musicList_<合集id>` 与 `收藏合集.musicListTableName` 列互为外键，删合集要同时 drop 表。
4. 自定义歌单名单的真源在 **SharedPreferences `custom_order`**，DB 里没有「有哪些歌单」的元表——重命名要同时改 SP + `ALTER TABLE`。
5. `待播放列表` 表每次启动被 `main()` 清空（12.5）。

## 易腐字段

- `TableName.*` 常量（表名字面量）；`DBName`（库文件名 musicOrder / collection）
- `musicItem2Row / row2MusicItem` 的字段集合（与 MusicItem 字段一一对应，新增字段两边都要动）
- `genMusicListTableName` 前缀 `musicList_`（`music_order/utils.dart` 的 `tabName.startsWith("musicList_")` 分支判断依赖它）
