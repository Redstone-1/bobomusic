# db · 模块地图（v3）

> 核对：2026-11-03，源码基线 `073cd0a`，补齐 schema v6、显示封面、playlistId family、多目录同步与 Windows 库位。当前库和迁移以 `lib/data/db/app_database.dart` 为准；旧版“表即歌单”模型已退役。

## 一句话模型

bobomusic3.db 的 schema version 为 6，当前五表：tracks、playlists、playlist_items、queue、play_history。曲目身份与歌单成员分离，四个 Repository 管理持久化语义，UI 通过 provider 与 Repository 使用数据。

## 入口与引用关系

```text
main.dart → initDesktopDatabaseFactory(Windows/Linux)
    → Windows：prepareWindowsDatabase；其它平台：默认库位
    → initAppDatabase → 全局 appDb；singleInstance=false；onConfigure 开 foreign_keys
data/repositories/
    ├─ TrackRepository → 曲目内容、喜欢、歌词、下载、本地同步
    ├─ PlaylistRepository → 自建歌单、成员与排序
    ├─ QueueRepository → 允许重复的待消费队列
    └─ HistoryRepository → 同曲最新历史、失败时 restore
消费方
    ├─ playlists_provider → 目录/详情/计数 family provider
    ├─ playback_provider → 曲目/队列/历史与恢复
    ├─ download_service → markDownloaded
    └─ 本地扫描/导入 → 同步或增量 upsert
```

## 表关系与关键文件

| 文件 / 表 | 职责 |
| --- | --- |
| `lib/data/db/app_database.dart` | 建库、外键开关与 schema 迁移 |
| `lib/data/db/desktop_database.dart` | Windows/Linux 生产使用 databaseFactoryFfi；测试才使用同步替身 |
| `lib/data/db/windows_database_path.dart` | 用户支持目录库位、唯一旧库快照迁移及失败保护 |
| `lib/data/repositories/` | Track/Playlist/Queue/History 四仓库 |
| `lib/data/local_audio_scanner.dart` | 元数据读取、指纹、目录排除；生产扫描走 isolate |
| `lib/data/local_audio_importer.dart` | 文件选择/复制，按指定文件增量导入 |
| tracks | 全局曲目、原始信息与 display 覆盖、origin、local_path、歌词/偏移、喜欢和下载标记 |
| playlists / playlist_items | 歌单定义与成员；成员 (playlist_id, track_id) 唯一 |
| queue | 允许重复 track_id，按 position 排序，消费即删 |
| play_history | track_id 主键，保存同曲最近 played_at |

playlist_items、queue、play_history 引用 tracks，歌单成员同时引用 playlists；删除外键实体由 CASCADE 清理引用。

## 关键状态链

- schema v1→v2 加 tracks.lyric_offset，v2→v3 建 play_history，v3→v4 清除已下线的 collection 歌单，v4→v5 加 display_name/display_author，v5→v6 加 display_cover；新建库直接建全量五表。这是 v3 数据库自身迁移，不等于已实现旧版 2.7.0 数据迁移。
- TrackRepository.upsert 命中后只更新 name/author/cover/duration/origin/updated_at，保护 liked_at、downloaded_at、created_at、display 覆盖以及已有本地路径/歌词。喜欢、下载、歌词使用专门写入口。
- “我喜欢”是 liked_at 非空的虚拟列表；已下载以 downloaded_at 和 local_path 查询。下载后的在线曲仍保留原 origin 与 id，播放器优先读本地路径。
- 本地 ID 为 `local:{大小}:{时长}:{归一化标题}:{归一化歌手}`，标题/歌手去空白并转小写。重扫不变的指纹保留喜欢与歌词。
- 扫描同步用事务 upsert，再求“库中 local ID − 本次扫描 ID”差集，删除只限 scannedRoots 内且不在 retainedPaths 的曲目；遇不可访问目录时 removeMissing=false，取消则不进入写库。排除 Android 目录和应用下载目录，避免重复导入下载曲；完整范围链见 [扫描与导入](./01-本地扫描事件流与扫描舱.md)。
- 文件选择导入只扫描所选/复制文件并逐项 upsert，不做全量 syncLocalTracks。同名不同内容使用递增后缀，大小与 MD5 相同则复用文件；复制使用异步 API，避免覆盖另一条已入库音乐。
- PlaylistRepository.addTrack 对重复成员返回 false，queue 则允许重复；队列 move 先记主键再顺移，takeFirst 在事务内删除并顺移。队列面板用 QueueEntry 暴露既有 queue.id；entries / entryById 保留条目身份，removeEntry / moveEntryToFront 在事务中按主键定位单次排队，旧 id 失效不误操作接替位置的条目。独立条目操作复用现有主键，不额外增加表或列。
- HistoryRepository.record 返回旧时间戳；装载失败 restore 恢复旧历史或删掉新记录。最近播放默认取最新 20 首，详见 [播放地图](../player/00-模块地图.md)。
- 播放会话队列另存 prefs 的 ID 快照和下标；queue 表是插队/稍后听的持久化待消费集合，不能相互替代。

## 显示覆盖与 UI 读取

- `Track.displayName/displayAuthor/displayCover` 与原始信息分开，effectiveName/effectiveAuthor/effectiveCover 优先覆盖字段；`updateDisplayInfo` 对 trim 后空值存 null。编辑器允许清空封面恢复原始，歌名不允许空；上游刷新和重扫不覆盖 display 字段。
- `lib/features/playlist/track_edit_dialog.dart` 保存后失效详情 family、歌单目录、待播、历史和已下载数据源；若当前会话引用该曲，再回库调用 `Playback.applyDisplayEdit` 热更新，不重新装载音频。测试入口：`test/features/playlist/track_edit_test.dart`。
- `PlaylistRepository.list` 汇总歌曲数量，并按成员 sort_index 读取首个有效封面 `COALESCE(display_cover, cover)`；只刷新详情会使桌面目录封面停在旧值，必须同时刷新 playlistsProvider。QueueRepository/PlaylistRepository 读 Track 同样要携带 display 字段。
- `playlistDetailTracksProvider` 的 family 参数为 String playlistId，内部统一分发 local/liked/custom 到 Repository；UI 不直接查库或为自建歌单另套 FutureBuilder，刷新期间保留已有数据。
- Windows 数据目录受 Runner.rc 的 CompanyName/ProductName 影响；迁移检查重构后数据模型的基础表，不包含旧版 2.7.0 格式转换，使用 VACUUM INTO 快照，不复制正在写入的主 DB。流程见 [桌面地图](../desktop/00-模块地图.md)。

## 易踩坑

- 待播单条操作不能按 trackId 批量删除，也不能在异步菜单中使用旧列表位置。队列主键和歌曲 ID 是不同身份，详见 [MEM-6](../bugs/MEM-6-播放队列更多误删.md)。
- **禁止按 NOT IN 分批删未再现曲目**：每批都会误删其它批。先求差集，再按 ID 的 IN 占位符分批删。
- getByIds 的 IN 查询返回无序，必须按输入 ID 重建顺序与重复条目；当前每批最多 900 个参数。
- 外键级联依赖 PRAGMA foreign_keys=ON，测试新连接也必须经过初始化；singleInstance=false 用于让独立内存库获得新实例。
- Repository 实例捕获创建时的 appDb，测试换库后重新创建实例，不能继续复用持有旧连接的仓库。
- 同名歌单约束与曲目重复、队列重复是三种不同语义，不要用单一去重逻辑覆盖。
- 旧版 2.7.0 表结构不在当前 onUpgrade 中处理；不要因出现 v1/v2/v3 字样就声称跨应用大版本迁移已完成。

## 排查入口

| 症状 | 先查 |
| --- | --- |
| 重扫后喜欢/歌词/成员丢失 | 指纹、upsert 保护字段、差集分批删除 |
| 导入少量文件却丢失旧本地曲 | 是否误用全量 syncLocalTracks |
| 删除后成员/队列/历史残留 | 外键开关、是否绕过 Repository |
| 最近播放出现失败歌曲 | _recordHistory 与 HistoryRepository.restore |
| 冷启动列表顺序/重复曲异常 | getByIds 保序、prefs 队列下标恢复 |
| 桌面数据库打不开或启动像空库 | ffi 初始化、Windows 目标库位、唯一旧库候选与启动错误页，不能静默覆盖旧库 |
| 改封面后桌面歌单卡没变 | display_cover 回库、COALESCE 查询、playlistsProvider 是否失效 |

自动化入口为 `test/data/` 和 `test/helpers/app_test_helper.dart`；旧版 2.7.0 真实用户库迁移仍未实现；Windows 已有 v3 库的快照迁移有独立测试，不能混为同一种迁移。
