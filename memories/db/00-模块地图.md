# db · 模块地图（v3）

> 表结构 SQL 见 `lib/data/db/app_database.dart`；本文补**语义约束**与**易踩坑**。基线：v3 四表 schema（S3）+ v2/v3 迁移，2026-10-27 核对。旧版「表即歌单」模型已退役，见 git 历史。

## 一句话模型

sqflite 单库 `bobomusic3.db`（version 3）：四表（tracks/playlists/playlist_items/queue）+ play_history；曲目与成员正交（一首歌全局一个身份，出现在 N 个列表），Repository 三件 + HistoryRepository 是唯一碰 SQL 的层。

## 引用关系（谁持有谁）

```
main.dart ──init──> initDesktopDatabaseFactory（Windows/Linux ffi）→ initAppDatabase
    │  全局 late appDb（singleInstance: false，测试重指内存库）；onConfigure 开 PRAGMA foreign_keys=ON
    ▼
lib/data/repositories/
    ├─ TrackRepository    upsert（只更新内容字段，liked/downloaded/created 永不覆盖）/ getByIds（保序、≤900 分批）
    │                     syncLocalTracks（事务 upsert + 差集分批删）/ setLiked / updateLyric(Offset) / markDownloaded
    │                     clearDownloaded / downloadedTracks
    ├─ PlaylistRepository create（name UNIQUE）/ addTrack（UNIQUE 冲突→false="已在歌单中"）/ reorder / items
    ├─ QueueRepository    允许重复；takeFirst（事务取队首并顺移，消费即删）/ append / insertNext / move（先记主键再顺移）
    └─ HistoryRepository  record（REPLACE 同曲留最新，返回旧时间戳）/ restore（回滚）/ recent（getByIds 保序）

消费方：playbackProvider（queue/history/track）、playlists_provider（目录/详情/计数 family provider）、
       download_service（markDownloaded）、local_audio_scanner（syncLocalTracks）
```

## 数据 / 状态链路

- schema 迁移：v1→v2 加 `tracks.lyric_offset`；v2→v3 建 `play_history`（track_id 主键 FK CASCADE + played_at）。onCreate 直接建全量。
- 「我喜欢」= `tracks.liked_at` 非空的虚拟列表（倒序）；下载 = `local_path + downloaded_at`；本地曲身份 = 内容指纹 `local:{大小}:{时长}:{归一化标题}:{归一化歌手}`（重扫保喜欢/歌词）。
- 播放历史：装载前乐观写、失败 restore 回滚（见 [[../player/00-模块地图]]）；最近播放 = played_at 倒序 limit 20。

## 易踩坑

- ⚠️ **删除「未再现」本地条目不能按 NOT IN 分批**——每批会把其它批当成未再现误删（>900 首首批即误删）。正确做法：先算差集再按 id 分批 IN 删（chunk 900，SQLite 变量上限 999）。
- ⚠️ FK 级联依赖 `PRAGMA foreign_keys=ON`（sqflite 默认关），必须留在 onConfigure；新建连接（测试重开库）都要走 initAppDatabase。
- ⚠️ `upsert` 语义：命中已存在只更新内容字段——复制这段代码时漏掉保护字段会洗掉用户喜欢/下载标记（历史教训：手写 insert map 漏 NOT NULL `updated_at` → 事务静默回滚、调用方拿不到异常）。
- ⚠️ `QueueRepository.move` 先记被移行主键再顺移（position 会易主）；`takeFirst` 消费即删，与播放状态机队列快照的一致性靠 `_load` 成功后立即 `_persistNow` 对齐。
- ⚠️ `getByIds` 保持传入顺序（IN 查询无序返回，需按 ids 重排）。

## 排查清单

| 症状 | 先查 |
| --- | --- |
| 删除歌单/曲目后引用残留 | 外键开关是否生效；是否绕过 Repository 直写 SQL |
| 重扫后喜欢/歌词丢失 | 指纹 id 是否变化；upsert 是否被改成全字段覆盖 |
| 最近播放出现没播成的歌 | `_recordHistory` 失败回滚链是否被绕过 |
| 队列顺序错乱 | move/takeFirst 的事务边界；position 顺移方向 |
| 桌面端打不开库 | initDesktopDatabaseFactory 是否在 initAppDatabase 之前 |

## 易腐字段

库名/版本号、`lyric_offset`/`play_history` 迁移分支、chunk 大小 900、`_fromRow` 列名映射、prefs 键（player 侧 `_kQueueIds`）。
