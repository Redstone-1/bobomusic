# db · 模块地图（v3）

> 核对：2026-10-29，v3 / `64d4a5e` 后的独立队列条目修复。当前库和迁移以 `lib/data/db/app_database.dart` 为准；旧版“表即歌单”模型已退役。

## 一句话模型

bobomusic3.db 的 schema version 为 3，当前五表：tracks、playlists、playlist_items、queue、play_history。曲目身份与歌单成员分离，四个 Repository 管理持久化语义，UI 通过 provider 与 Repository 使用数据。

## 入口与引用关系

```text
main.dart → initDesktopDatabaseFactory(Windows/Linux) → initAppDatabase
    └─ 全局 appDb；singleInstance=false；onConfigure 开 foreign_keys
data/repositories/
    ├─ TrackRepository → 曲目内容、喜欢、歌词、下载、本地同步
    ├─ PlaylistRepository → 歌单/合集、成员与排序
    ├─ QueueRepository → 允许重复的待消费队列
    └─ HistoryRepository → 同曲最新历史、失败时 restore
消费方
    ├─ playlists_provider → 目录/详情/计数 family provider
    ├─ playback_provider → 曲目/队列/历史与恢复
    ├─ download_service → markDownloaded
    └─ 本地扫描/导入 → 同步或增量 upsert
```

## 表关系与关键文件

| 文件 / 表 | 职责 |
| --- | --- |
| `lib/data/db/app_database.dart` | 建库、外键开关与 schema 迁移 |
| `lib/data/db/desktop_database.dart` | 桌面 ffi 工厂初始化 |
| `lib/data/repositories/` | Track/Playlist/Queue/History 四仓库 |
| `lib/data/local_audio_scanner.dart` | 元数据读取、指纹、目录排除；生产扫描走 isolate |
| `lib/data/local_audio_importer.dart` | 文件选择/复制，按指定文件增量导入 |
| tracks | 全局曲目、origin、local_path、歌词/偏移、喜欢和下载标记 |
| playlists / playlist_items | 歌单定义与成员；成员 (playlist_id, track_id) 唯一 |
| queue | 允许重复 track_id，按 position 排序，消费即删 |
| play_history | track_id 主键，保存同曲最近 played_at |

playlist_items、queue、play_history 引用 tracks，歌单成员同时引用 playlists；删除外键实体由 CASCADE 清理引用。

## 关键状态链

- schema v1→v2 加 tracks.lyric_offset，v2→v3 建 play_history；新建库直接建全量五表。这是 v3 数据库自身迁移，不等于已实现旧版 2.7.0 数据迁移。
- TrackRepository.upsert 命中后只更新 name/author/cover/duration/origin/updated_at，保护 liked_at、downloaded_at、created_at 以及已有本地路径/歌词。喜欢、下载、歌词使用专门写入口。
- “我喜欢”是 liked_at 非空的虚拟列表；已下载以 downloaded_at 和 local_path 查询。下载后的在线曲仍保留原 origin 与 id，播放器优先读本地路径。
- 本地 ID 为 `local:{大小}:{时长}:{归一化标题}:{归一化歌手}`，标题/歌手去空白并转小写。重扫不变的指纹保留喜欢与歌词。
- Android 全量扫描同步用事务 upsert，再求“库中 local ID − 本次扫描 ID”差集分批删除；排除 Android 目录和应用 Download/啵啵音乐目录，避免重复导入下载曲。
- 文件选择导入只对新复制文件扫描并逐项 upsert，不做全量 syncLocalTracks，否则会把其它本地条目当成消失而删除。
- PlaylistRepository.addTrack 对重复成员返回 false，queue 则允许重复；队列 move 先记主键再顺移，takeFirst 在事务内删除并顺移。队列面板用 QueueEntry 暴露既有 queue.id；entries / entryById 保留条目身份，removeEntry / moveEntryToFront 在事务中按主键定位单次排队，旧 id 失效不误操作接替位置的条目。schema 未变。
- HistoryRepository.record 返回旧时间戳；装载失败 restore 恢复旧历史或删掉新记录。最近播放默认取最新 20 首，详见 [播放地图](../player/00-模块地图.md)。
- 播放会话队列另存 prefs 的 ID 快照和下标；queue 表是插队/稍后听的持久化待消费集合，不能相互替代。

## 易踩坑

- 待播单条操作不能按 trackId 批量删除，也不能在异步菜单中使用旧列表位置。队列主键和歌曲 ID 是不同身份，详见 [MEM-6](../bugs/MEM-6-播放队列更多误删.md)。
- **禁止按 NOT IN 分批删未再现曲目**：每批都会误删其它批。先求差集，再按 ID 的 IN 占位符分批删。
- getByIds 的 IN 查询返回无序，必须按输入 ID 重建顺序与重复条目；当前每批最多 900 个参数。
- 外键级联依赖 PRAGMA foreign_keys=ON，测试新连接也必须经过初始化；singleInstance=false 用于让独立内存库获得新实例。
- Repository 实例捕获创建时的 appDb，测试换库后重新创建实例，不能继续复用持有旧连接的仓库。
- 同名歌单约束与曲目重复、队列重复是三种不同语义，不要用单一去重逻辑覆盖。
- 旧版 2.7.0 表结构不在当前 onUpgrade 中处理；不要因出现 v1/v2/v3 字样就声称跨应用大版本迁移已完成。

## 排查入口

| 症状 | 先查 |
| --- | --- |
| 重扫后喜欢/歌词/成员丢失 | 指纹、upsert 保护字段、差集分批删除 |
| 导入少量文件却丢失旧本地曲 | 是否误用全量 syncLocalTracks |
| 删除后成员/队列/历史残留 | 外键开关、是否绕过 Repository |
| 最近播放出现失败歌曲 | _recordHistory 与 HistoryRepository.restore |
| 冷启动列表顺序/重复曲异常 | getByIds 保序、prefs 队列下标恢复 |
| 桌面数据库打不开 | ffi 初始化顺序和 appDb 是否已重指 |

自动化入口为 `test/data/` 和 `test/helpers/app_test_helper.dart`；本轮未对旧版真实用户库做迁移验证。
