# player · 模块地图（v3）

> 核对：2026-11-03，源码基线 `073cd0a`，补齐桌面共用、音量/退出、显示封面、歌词定位和酷我试听探测。历史失败回退与队列约束继续保留；Windows 本机 Release 编译不代替五源、媒体键及听感验收。旧版 BBPlayer / PlayerModel 已退役。

## 一句话模型

Playback 是 Riverpod keepAlive 状态机，持有播放会话与恢复快照；AudioEngine 负责装载/播放和事件流，JustAudioEngine 使用 just_audio，本地文件直读，网络流经 RangeProxySource；UI 消费 playbackProvider，歌词由独立 controller 管理。

## 入口与引用关系

```text
  ├─ _recordHistory → TrackRepository / HistoryRepository
  ├─ systemMediaCenter.sync → 原生系统媒体会话；命令反向接回 Playback
  └─ prefs 快照 → 冷启动恢复曲目、位置、模式、会话队列与下标；独立保存全局速度、音量和静音前音量

  └─ queue_sheet → queueEntriesProvider / QueueRepository + Playback 队列命令
app_shell.dart / desktop_shell.dart → listen(error/VIP) → AppToast
```

## 数据与状态链

- _load 先记 prev，乐观写历史，再发布新曲 buffering 态；解析源 → engine.load → 串行恢复当前 speed/volume → play 命令发出后清 buffering、乐观写 playing、记录 _loadedKey 并立即持久化。AudioEngine.play 完成只表示命令发出，后续失败通过 errorStream；不能等待 AudioPlayer.play 的整段播放生命周期。
- **源解析阶段失败**：引擎还没被 load 替换，回滚历史并恢复旧曲/队列/进度，保留 prev.playing。
- **进入引擎 load 后失败**：旧源可能已停，恢复旧会话但强制 playing=false。失败路径清空 _loadedKey；下次 toggle 发现当前曲尚未装载，重新解析并 load，不能仅对无源引擎调用 play。
- 两种失败都会挂 error、持久化回退快照并同步系统会话；应用壳提示后清错。B 站 -404 额外翻译为原视频可能丢失。
- 运行时引擎错误清 _loadedKey 并保存 _failedSourceKey；提示清错不清此标记。重新装载失败曲时跳过 B 站直链缓存，成功后清标记。JustAudioEngine 通过播放代次丢弃旧 play Future 的迟到错误，见 [MEM-4](../bugs/MEM-4-B站与播放链路回归.md)。
- 取流优先 track.localPath；旧 Track 没路径时回库补查。文件存在则离线直读；在线曲路径失效后按 origin 回退所属源，本地曲缺文件时报错。
- **会话队列**是当前点歌上下文，快照以 id 列表和下标存 prefs；**queue 表**是插队/稍后听的待消费条目，可重复、takeFirst 消费即删。切歌先消费 queue，再走播放模式策略。
- 冷启动回库恢复曲目和会话队列，剔除已删曲，优先使用保存下标区分重复曲目；快照损坏或不含当前曲则退为单曲，恢复为暂停态。引擎惰性创建，点击播放才重新装载。
- position 事件驱动歌词和进度，写盘采用去抖，暂停/切歌/dispose 立即写。dispose 使用缓存快照，不能再读已销毁的 provider state。

## 队列菜单与条目身份

- 播放卡队列入口进入 queue_sheet.dart；待播放来自 queueEntriesProvider → QueueRepository.entries → QueueEntry(id, track)。搜索、歌单、播放卡和播放内核所有队列写入口统一刷新该 provider。
- 待播更多先打开菜单，取消不改数据。下一首播放移动所选主键到队首，移除本条只删除该次排队；已消费的旧条目返回无效，不按当前位置或 trackId 猜测。
- 待播点播回库检查主键，插入当前会话之后；_load 返回成功后才移除该条。取流或装载失败保留待播记录。成功指播放命令已发出，后续流错误仍按原机制处理。
- 会话点播和移除按明确下标定位重复歌曲，并校验菜单打开时的列表引用。移除非当前条目保持音频与进度，修正下标后立即持久化；当前条目不提供移除。会话菜单的下一首播放新增一条待播记录。
- 面板保留待播空态、加载与失败重试；操作菜单只关闭子层，成功点播才关闭队列面板。队列计数跟随当前会话更新，进度事件不重建列表。
- 历史误删与回归入口见 [MEM-6](../bugs/MEM-6-播放队列更多误删.md)。

## 全局倍速与时间轴

- 播放卡动作行使用仪表盘倍速图标，非正常速度时按主题色高亮；进入七档吸附滑杆（0.5 / 0.75 / 1.0 / 1.25 / 1.5 / 1.75 / 2.0×）。稍后入口使用列表播放图标，仍按原逻辑插入待播放队首。速度由 PlaybackState.speed 持有，独立存入 SharedPreferences 的 playback_speed，默认 1.0。损坏偏好恢复默认，命令只接受有限的 0.5～2.0 数值。
- 滑杆拖动只更新面板内部预览，松手或点刻度后才调用 setSpeed，面板保持展开供试听；文字入口可恢复正常速度。预览与实际状态分离，迟到的提交不能覆盖新拖动；确认完成后回显实际速度，失败回到上次成功值。空闲面板跟随系统调速，关闭后的结果不再访问组件。
- setSpeed 与装载后的速度恢复共用串行队列；引擎确认后才更新 state、系统会话和偏好。无引擎时只更新偏好，不为调速创建引擎；销毁后的迟到结果不再写状态或偏好。切歌失败回退会话时保留期间成功修改的全局速度。
- JustAudioEngine.setSpeed 不重新装载或 seek；just_audio 的内部速度会先于平台结果更新，失败时需尝试恢复旧值，再交由 Playback 报错。平台失败保持上次成功值；偏好保存失败则保留已生效速度并提示保存失败。
- 每次 load 后、play 前重新应用当前速度，跨切歌、暂停续播与冷启动保持偏好。系统媒体通道的 setSpeed 回到同一命令；系统快照使用实际 speed 推算进度，不能继续固定为 1.0。
- position、duration、LRC 偏移始终是媒体时间，不额外乘倍速；定时关闭的截止时间仍按现实时间。迷你歌词横向动画的总时长除以 speed，切换时保留控制器进度，暂停仍停止动画。
- 回归入口：`test/player/playback_speed_test.dart`、`test/player/playback_speed_widget_test.dart`、`test/player/playback_speed_lyric_widget_test.dart`、`test/player/system_media_center_test.dart`、`test/player/just_audio_engine_test.dart`。原生变速听感与后台系统行为由所有者验证。

## 歌词链

- App 常驻 `playerPresentationCoordinatorProvider` 监听当前 Track，在微任务中刷新最近播放并 `loadFor`；迷你条/播放卡仍可调用该入口。`loadFor` 对相同 trackId 的在途加载也去重，不能让第二个视图取消第一个视图的请求。
- loadFor 优先回库读取歌词和偏移，缺失才搜索候选并匹配；异步返回通过请求序号和 trackId 防止旧曲覆盖新曲。
- 长句在 _ScrollingLyricText 内停顿 → 滚至尾部 → 停驻，暂停时停止、续播继续；AnimatedSwitcher 固定左对齐，避免短歌词切换时跳位。
- `PlayerLyricsView` 的 `showTools` 支持将 `PlayerLyricTools` 移到桌面左列，让展开页歌词占满高度。普通行高 56，展开行高 76；桌面上下留白为 `(视口高度 − 行高) / 2`，滚动目标包含留白和半行高，首句/末句也能居中。
- 自动滚动记录 active、视口尺寸、行高、trackId 和歌词列表引用；同一目标不重复发起动画，换歌词/缩放立即重定位，换当前句才平滑滚动。不能仅因进度事件到来就重启动画。回归入口：`test/desktop/player_lyric_alignment_test.dart`。
- 歌词工具面板为两列三行：提前/延后 0.5s、提前/延后 2s、搜索替换/右下删除；偏移仍按曲目入库。
- LRC 解析、翻译合并与候选匹配见 `lib/origin_sdk/lyric/`；歌词存曲目层，多个歌单共享。

## 音量、退出与显示更新

- `PlaybackState.volume` 为有限的 0～1 数值，`playback_volume` 和 `playback_last_audible_volume` 分别保存当前及静音前音量；损坏偏好恢复默认。音量变更串行执行，引擎成功后才更新状态/偏好，无引擎时只改偏好，不为拖动滑杆创建播放器。切歌失败回退保留期间成功修改的速度和音量。
- `prepareForExit` 等待 seek、音量、倍速命令，暂停后刷新快照，并等待当前曲目/位置/模式/会话队列/下标写盘。保存失败抛错，Windows 壳提示并阻止销毁窗口；不能只依赖 dispose 中未等待的写盘。回归见 `test/player/playback_volume_test.dart`。
- 显示名称/歌手/封面由 effective 字段统一读取，`applyDisplayEdit` 热更新当前曲和会话列表并同步系统媒体，不重新装载音频。原始信息和持久化刷新链见 [数据地图](../db/00-模块地图.md)。
- 手机播放卡保留上滑下一首、下滑上一首；共享内容不搬走手机手势包装。更多菜单包含加入歌单、编辑信息与定时关闭，B 站视频入口位于动作行倍速后，仅 B 站源展示。

## 酷我试听片段探测

只有酷我曲目在元数据和引擎时长均为正、实际时长不足标注 70% 时，Playback 才登记到会话内 `vipLimitedTrackIdsProvider`，同曲去重；手机壳和桌面壳监听新增项提示，榜单行消费该集合显示灰态和 VIP 标记。该集合重启清空，属于播放期时长推断，不是服务端付费鉴权或可提前覆盖所有试听的判定；不能据此声称解除 VIP 限制。当前酷我双榜已从广场下线，搜索/播放仍保留，见 [广场地图](../plaza/00-模块地图.md)。

## 易踩坑

- 共用播放卡动作入口（含独立倍速和 B 站源专属视频入口）通过 Expanded 等分，并共用 _PlayerActionButton 的 32×32 图标槽、最小高度与文字行高。不能回到自然宽度加 spaceAround：不同按钮宽度会使中心不等距。稍后列表播放字形留白较多，iconSize 单独校正为 30，放大不改变槽位或文字位置；倍速仍独立订阅状态后复用同一按钮。布局回归覆盖窄屏、放大字号及喜欢选中态。
- playingStream 在同引擎切源/重复 play 时不保证重新发 true；命令成功侧的 playing 与 buffering 需要保持一致，否则歌词/进度可能停住。
- 不要把“整态回退”写成“旧曲一定继续播”；是否进入 engine.load 决定回退播放态。
- RangeProxySource.request 的 end 排尾，发 HTTP Range 才减一；CDN 返回 200 时裁掉 start 前缀。响应头后断流从已交付位置续接备用 URL，总长不同拒绝拼接，无备用链则向下游报错。
- 缓存写入失败不影响传流，上游失败不能被当作缓存异常吞掉。每次请求独立 .part 文件，只有完整已知总长的流才转正缓存。
- RangeProxySource.cacheDir 是 static late，使用缓存的测试必须先指定临时目录；不是每个 buildTestApp 都会经过 main 初始化。
- 最高音质优先策略使用 MD5(`曲目 key|highest-v1`) 作为缓存名，跳过旧的 MD5(key) 缓存，不主动删除旧文件；已下载到 localPath 的文件仍优先离线直读。**当前只有 kuwo: 前缀使用 .mp3，其余使用 .m4a**。网易/QQ/千千即使 contentType=audio/mpeg，也仍按现有规则生成 .m4a 缓存名，不应将扩展名描述为实际格式判定。
- 下载模块用同一个 cacheFileFor 命中并复制；任务暂停、取消和续传是另一条生命周期，见 [下载地图](../download/00-模块地图.md)。变更缓存命名时一起核对下载和清理逻辑。
- B 站缺 cid 自愈在 SDK；播放和下载都要按 Track.origin 分发五源，不能默认其它源都走 B 站。

## 排查入口

| 症状 | 先查 |
| --- | --- |
| 冷启动有曲目但点播放无声 | _loadedKey、toggle 是否走完整装载与 initialPosition |
| 切歌失败后 UI 仍显示在播 | reachedEngine 与失败分支 playing，历史是否 restore |
| 进度/歌词停在旧位置 | buffering 清除、position 订阅与歌词 trackId/请求序号 |
| 待播放条目消失或顺序错 | queue 主键、菜单操作与会话快照，见 [MEM-6](../bugs/MEM-6-播放队列更多误删.md) |
| 长歌词尾字被裁/暂停仍滚 | _ScrollingLyricText 的宽度、尾距、动画恢复与 speed |
| 倍速切歌或重启后丢失 / 系统进度漂移 | playback_speed、装载后 _queueSpeed、系统媒体快照的 speed |
| 下载后离线仍取网 | localPath 回库补查、文件存在性、下载登记 |
| 通知栏无响应 | systemMediaCenter.commands 绑定、Android 通知权限和原生通道同步 |

测试入口：`test/player/`、`test/lyric/`、`test/helpers/fake_engine.dart`、`test/helpers/app_test_helper.dart`。带常驻动画的 widget 测试用固定 pump，不用 pumpAndSettle。
