# dev_memory：模块记忆文档

把一次排查/开发中**已经掌握**的模块知识写成常驻文档，让后续遇到相似问题时能快速识别「这是哪条链路、该看哪些文件」。

> 记忆是**项目资产**：写在**本仓库根目录的 `memories/`** 下，随仓库一起版本化。
> 与 `project` 文档的关系：`项目文档.md` 是全景事实源，记忆文档是**某个模块/缺陷的下钻补充**——`项目文档.md` 不会因一次排查而更新，记忆文档会。
> 记忆文档**不会自动加载**，所以索引必须逐层登记，否则等于不存在。

## 何时用

- 用户说：「形成记忆文档」「记录一下」「沉淀经验」「方便后续类似问题快速识别」
- 修完一个 bug / 做完一轮代码调研后，用户要求把该模块知识落成文档
- 用户说：「新建 xxx.md」「记忆该放哪」

## 产出位置：先分类，再落盘

| 类型 | 判据 | 落到哪 | 命名 |
|---|---|---|---|
| **缺陷记忆** | 由**具体缺陷**排查得来：有 bug 编号、有「现象 → 根因链 → 修复」 | `memories/bugs/` | `<主题>.md` |
| **模块结构记忆** | 该模块**长期长什么样**：目录地图、链路、状态流、跨文件关联 | `memories/<模块>/`（一个模块一个目录） | 成组时用 `NN-<主题>.md`（如 `00-模块地图.md`、`01-<主题>.md`） |
| **单组件 / 单能力记忆** | 一个组件的内部机制与坑 | 归到它所属模块目录（通用组件归 `memories/components/`） | `<组件名>.md`，与源码文件名一致 |

**同一件事两边都沾时**：缺陷视角（这次怎么坏的）进 `bugs/`，结构视角（它平时怎么转）进模块目录，**两边互链、不复制**。

模块目录名对齐 `lib/` 分层：`player`、`music_order`、`music_plaza`、`origin_sdk`、`db`、`event_bus`、`components`、`utils` 等。

| 项 | 约定 |
|---|---|
| 粒度 | **一个主题一份**；粒度过大就拆分；同一模块的多个缺陷若指向同一条链路，**合并成同一篇** |
| 互引 | 相关主题用 `[[另一篇]]` 互相引用（跨目录也可） |
| **索引** | **逐层登记**：文档所在子目录的 `README.md` 加一行（文档 / 覆盖主题 / 什么时候读）；**新建子目录**时还要在上一层 `README.md` 加一行 |
| 新目录 | 新模块目录必须建 `README.md`（写入覆盖范围 + 索引表 + 该模块的「不写什么」） |
| 根索引 | `memories/README.md` 为总索引，登记各子目录 |

## 编写要求（中等详细）

**必须包含**（按此顺序；模块结构类文档可按需合并 4/5 段）：

1. **一句话模型** —— 这个模块/组件到底做什么
2. **配置 / 入口** —— 入口文件或配置项在哪个文件
3. **核心组件与文件** —— 路径 + 职责（表格）
4. **关联与引用关系** —— ⭐ **重点**：上下游、谁调用谁、谁渲染谁（ASCII 图或表格）
5. **数据 / 尺寸 / 状态链路** —— 关键自变量如何一层层传下去
6. **易踩坑** —— 标 ⚠️，写清「现象 → 根因链 → 为何只在某场景出现 → 修复」
7. **排查清单** —— 「症状 → 先查哪里」对照表
8. **易腐字段** —— 会随代码变化的类名/方法名/路径/行号

**要写**：

- 组件、文件、模块之间的**关联与引用关系**（本类文档的核心价值）
- 缺陷结论**带编号**（沿用 `项目文档.md` 第 12 章的编号，或自建 `MEM-<n>` 编号）
- 路径一律用**仓库相对路径**（如 `lib/modules/player/instance.dart`）

**不要写**：

- 逐行代码解读、参数默认值逐条罗列
- 轻易就能 grep 到的细节
- **给薄壳 / 直白组件单独开文档**（能一眼看懂的，只在模块地图里占一行）
- 推测性内容；**未核实的点显式标注「未展开」**，并说明缺哪类证据
- 与 `项目文档.md` 大段重复的全景内容（引用而非复制）

## 流程

1. **汇总事实**：列出本次调研到的文件、grep 结果、关键代码位置；大模块**不必全读**，按入口 / 状态层 / 关键容器定向取证，读不到的标「未展开」
2. **分类**：按上表判断落 `bugs/` 还是模块目录
3. **组织**：按上面 8 段结构组织，先画关联关系图
4. **写入**：`memories/<目录>/<文件名>.md`
5. **登记索引**：本层 `README.md` 加一行；新目录还要登记到 `memories/README.md`
6. **互引**：与相关文档建立 `[[链接]]`

## 校验（人工，无脚本）

本项目**没有记忆校验脚本**，落盘后自查：

- 每个新建的文档都在其所在目录的 `README.md` 出现
- 每个新建的子目录都在上一层（含 `memories/README.md`）出现
- 索引里的相对链接都能解析（无悬空链接）

## 范例

- 缺陷记忆：`memories/bugs/<主题>.md` —— 8 段结构里第 6 段「易踩坑」是主体，结论带编号
- 模块结构记忆：`memories/<模块>/00-模块地图.md` —— `00-` 入口 + `NN-` 编号链路文档
- 可参考 `项目文档.md` 第 4~6 章的写法（但不复制其内容）

## 易腐字段（季度核对）

- 记忆目录（`memories/`）、分层结构与索引名（`README.md`）
- 归档判据（缺陷 → `bugs/`；结构 → 模块目录）与 `NN-` 命名约定
- 上述 8 段结构与「要写 / 不要写」边界
